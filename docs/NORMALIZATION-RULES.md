# Heading and text normalization rules

The spec for the extraction pipeline that turns Vietnamese administrative and
legal documents (PDF/DOCX) into input for a RAG stack. This is binding — do not
relax it casually; every number in here has a reason attached.

Throughout, the Vietnamese keywords (`PHẦN`, `CHƯƠNG`, `ĐIỀU`, `Phụ lục`, `MỤC`)
are part of the *input format*, not user-facing text. They stay in Vietnamese
because the documents do.

## 0. Invariants

1. **No text is lost.** Every normalization step may change *form* only, never
   remove content. When a heading is demoted or merged away, its heading line
   moves down into the body, section number included.
2. **One chunk, one topic.** Topics are defined by the outline, so chunk quality
   depends directly on whether headings are detected correctly.
3. **A false positive is worse than a miss.** A sentence mistaken for a
   high-level heading *swallows every section after it* as its children, and
   the titles of a great many chunks below go wrong with it. Missing a heading
   only attaches that section to its parent.
4. **Real structural signals beat inferred typography.** A number generated by
   Word (`numbering.xml`) is the document's real structure — always trust it.
   A number inferred by regex over PDF text is a guess — it must pass the
   filters.

---

## 1. Character normalization

Run in exactly this order, on **every** string taken out of the file:

1. **Strip invisible characters**: U+200B (zero-width space), U+200C, U+200D,
   U+FEFF (BOM), U+00AD (soft hyphen).
2. **NFKC normalize.** This handles most of it: mathematical letters
   (Mathematical Alphanumeric Symbols — an Equation Editor formula yields `𝐌𝐢`
   rather than `Mi`, and a RAG stack with no font for that block reads it as
   `$Mi$` or drops it), fullwidth digits, ligatures, non-breaking spaces.
3. **Unwrap Private Use Area glyphs** (U+E000–U+F8FF). The Symbol/Wingdings
   fonts embedded by Word push their glyphs into U+F0xx while **keeping their
   ASCII code positions**:
   - `U+F020`–`U+F07E` → `chr(code - 0xF000)`, **but only punctuation and
     digits are taken back**; if the result is a letter, substitute a space (the
     letter range is the Greek alphabet or Wingdings ornaments, and folding
     those to Latin invents a word that is nowhere in the document).
   - Explicit exceptions: `U+F0B7`→`-`, `U+F0A7`→`-`, `U+F0D8`→`->`,
     `U+F0E0`→`->`.
   - Anything else in the PUA → space.
4. **Fold symbols to words or ASCII equivalents** (lookup table):
   - Maths: `∑`→` Tổng `, `∏`→` Tích `, `√`→` căn `, `∞`→` vô cùng `,
     `≤`→`<=`, `≥`→`>=`, `≠`→`!=`, `≈`→`~=`, `±`→`+/-`, `×`→`x`, `÷`→`/`,
     `∗`→`*`, `→`→`->`, `⇒`→`=>`.
   - Dashes of every kind (`‐ ‑ ‒ – — − ―`) → `-`.
   - Typographic quotes (`“ ” „ « »`) → `"`; (`‘ ’ ‚ ′`) → `'`; `″` → `"`.
   - Bullets (`• ▪ ● ◦ ○`) → `-`.
5. **Collapse whitespace**: NBSP and tab → space; two or more consecutive
   spaces → one; `strip()` both ends.

Rules: do **not** strip Vietnamese diacritics, do **not** lowercase, do **not**
drop punctuation, do **not** change `Đ/đ`. Normalization exists so the RAG stack
can tokenize, not so strings can be matched.

## 2. Line and paragraph normalization

### 2.1 Rejoining lines the PDF wrapped

A PDF stores rendered lines, so one sentence often spans two blocks. Join
`follow` onto `lead` when **both** conditions hold:

- `lead` does **not** end with `[.:;!?]` (trailing whitespace allowed).
- `follow` does **not** open a new item, i.e. does not match:
  `^\s*([-–—•+*] | \(?[a-zA-Zđ][.)]\s | \(?[ivx]+[.)]\s | \d+(\.\d+)*[.)]?\s)`

Do **not** use a leading capital as a condition: the second half of a sentence
very often starts with a proper noun ("…Dai-ichi Life Việt" / "Nam được…").

### 2.2 Flattened tables

Each table row becomes one line, columns separated by ` | `, each column in the
form `Column name: value`. In a markdown table, drop columns that are entirely
empty (merged cells in Word/PDF extract as runs of empty adjacent columns).

## 3. Heading detection

### 3.1 Rank table (lower number = higher level)

| rank | Kind | Example |
|---|---|---|
| -1 | banner (unnumbered banner heading) | `TỔNG QUAN VĂN BẢN QUY ĐỊNH` |
| 0 | part | `PHẦN 1`, `Phần I` |
| 1 | chapter / appendix | `CHƯƠNG I`, `Phụ lục 01`, `PL02.1003.PCS.2026(1)` |
| 2 | section | `MỤC 1` |
| 3 | roman-upper | `I.` `II.` `III.` |
| 4 | article | `ĐIỀU 5` |
| 10 | decimal | `1.` `2.1.` `2.3.1.` |
| 25 | letter-upper | `A)` `B)` |
| 30 | letter | `a)` `b)` |
| 50 | roman | `(i)` `(ii)` |

**The marks must be spaced widely**, because a Word list level is *added on top*
of the mark. Two different marker kinds must never land on the same number, or
two distinct levels collapse into one when the tree is built.

For decimal numbers, rank = `10 + (number of dots)`, so `2.1` sits one level
below `2`.

### 3.2 Detection patterns

```
^(PHẦN|Phần)\s+([0-9IVXivx]+)\s*[:.\-–]?\s*(.*)$
^(CHƯƠNG|Chương)\s+([0-9IVXivx]+)\s*[:.\-–]?\s*(.*)$
^(PHỤ LỤC|Phụ lục)\s*([0-9IVXivx]*)\s*[:.\-–]?\s*(.*)$
^(PL)\s*([0-9][0-9.()A-Za-z]*)\s*[:\-–]\s*(.*)$      # internal code
^(MỤC|Mục)\s+([0-9IVXivx]+)\s*[:.\-–]?\s*(.*)$
^(ĐIỀU|Điều)\s+(\d+)\s*[:.\-–]?\s*(.*)$
^(\d+(?:\.\d+)*)\.?\s+(\S.*)$                        # decimal
^(\d+(?:\.\d+)*)\.?$                                 # decimal, name on next line
^(\(?[ivxIVX]{1,5}[.)])\s+(\S.*)$                    # roman
^([a-zA-Z][.)])\s+(\S.*)$                            # letter
```

Mandatory notes:

- The `PL...` pattern must **not** accept a dot as its separator (only `:` `-`
  `–`): the dot is part of the code itself, and accepting it makes a
  cross-reference like "…theo Phụ lục số PL01.1016.PDS.2026(1);" match too,
  spawning a high-level branch that swallows every section after it.
- A solid code stays solid (`PL02.1003.PCS`); do **not** split it into `PL 02`,
  or lookups by code stop matching.
- A marker keeps its punctuation (`c.`, not `c`) so the heading reads exactly as
  it does in the source document.

### 3.3 Telling `I.` from `i)`

- Uppercase token **and** matching `^(?=[ivx])x{0,3}(ix|iv|v?i{0,3})$`
  (I..XXXIX) → roman-upper (rank 3, a high level in administrative documents,
  ranking above even `1.`).
- Token longer than one character, or opening with a bracket → roman (rank 50,
  the deepest level).
- A bare `i)` → **treat as letter** (rank 30): it is usually just the ninth item
  of an `a) b) c)…` list, and giving it a level of its own spawns a phantom tier
  in the middle of that list.

### 3.4 False-positive filters

Reject a heading candidate when:

- It opens with a cross-reference word:
  `^(theo|tại|quy định tại|căn cứ|xem|nêu tại|như)\b` (case-insensitive).
- For `part | chapter | article | section | roman-upper`:
  - No name attached → reject. ("PHẦN 1" and "ĐIỀU 5" appear constantly inside
    cross-references such as "…quy định tại Điều 2.3 Phần 1 này"; once the PDF
    wraps the line, that fragment looks exactly like a heading.)
  - First character of the name (after stripping `“ " ' (`) is lowercase →
    reject.
  - If the number was **not** generated by Word: it must be bold **or** at least
    80% of the name's letters must be uppercase. A real heading in a PDF is
    always emphasised.
- If the number **was** generated by Word → accept immediately, skipping the
  typographic filters below (Word has declared this a numbered item; that signal
  is far stronger than anything inferred from typography, above all in documents
  that do not set their headings in bold).
- Whole line longer than 250 characters → reject.
- `letter | roman` and not bold → reject (extremely common in plain
  enumerations; accepting them shreds the content into hundreds of tiny
  sections).
- `decimal` and not bold:
  - A colon separates name from content → measure the **part before the colon**;
    reject beyond 60 characters. (Measuring the whole line rejects every heading
    of the shape "1.9 Hợp đồng bảo hiểm: là tất cả văn bản…", taking its whole
    subtree with it.)
  - No colon → the whole line is the name; reject only beyond **160
    characters**. Long section names are routine in legal texts.
  - Name starts in lowercase → reject.

The colon separating name from content must match `(?<!\d):(?!\d)` — skip a
colon between two digits (`8:30`, `1:2` are times and ratios).

### 3.5 Sequence continuity check

Applies only to numbers **inferred from typography** (Word-generated numbers are
always kept).

A sentence opening with a number ("30 (ba mươi) ngày tuổi đến 70 tuổi…") looks
exactly like a heading once the PDF wraps the line. Two rules reject it:

- **A zero-padded number** (`(^|\.)0\d`) is not a section number. "04 (bốn) Năm
  hợp đồng đầu tiên" is a quantity; section numbers are never zero-padded.
- **It must continue the open sequence.** Given the current `num` and the
  preceding `prev` (as integer tuples, `2.3.1.` → `(2,3,1)`):
  - Same branch (`num[:d-1] == prev[:d-1]`, `d = len(num) ≤ len(prev)`): valid
    when `num[-1] == 1` (restarting the sequence) or
    `prev[d-1] < num[-1] ≤ prev[d-1] + 2` (leaving room for one section that
    extraction missed).
  - First child of a different branch (`num[-1] == 1`, `2 ≤ d ≤ len(prev)+1`):
    valid when its parent branch also continues the sequence (checked
    recursively) — e.g. `2.2.5` then `2.3.1` when the `2.3` heading was missed.
  - Anything else → reject.
- On a heading of another kind (PHẦN/ĐIỀU/Phụ lục…), **reset** `prev = None`:
  it opens a new sequence.

### 3.6 Banners — unnumbered top-level headings

**All three** cues must be present (ordinary prose never satisfies all three, so
this rule almost never misfires — which matters, because a misdetected banner
swallows the whole part of the document that follows it):

1. Font size **clearly larger** than the body size (`body_size` = the size
   covering the most characters across non-table `para` blocks).
2. At least 80% of letters uppercase.
3. Carries no section number (matches none of the patterns in §3.2).

Plus these backstops:

- Length 3–120 characters; letters as a fraction of all characters ≥ 0.5.
- At least two words of two or more characters, all letters (the formula
  `L = M *T *R` is also large and all caps).
- Not a table cell, not a figure.
- **Join adjacent banner lines** on the same page into one heading ("QUY ĐỊNH" /
  "SẢN PHẨM TIẾT KIỆM LINH HOẠT" at two different sizes — the ordinary
  line-joining step leaves them apart because the sizes differ). The text moves
  up onto the first line; the following lines are cleared.
- **Accept only when the document has at least 2 banners.** A document with
  exactly one banner has that banner as its title — which is already the root of
  the tree; giving it another branch grows one redundant level, while the tree
  only goes 3 deep.

## 4. Word numbering (DOCX)

When Word numbers a list automatically, the markers `1.`, `2.1.`, `a)` are **not
in the paragraph text** — Word generates them at display time. Reading the file
with plain `python-docx` loses every section number, leaving the RAG stack with
no hierarchy signal. They have to be rebuilt from `numbering.xml` following the
OOXML rules:

- Read `w:abstractNum` → `{ilvl: (numFmt, lvlText, start, lvlRestart, pStyle)}`;
  `w:num` → the `numId → abstractNumId` mapping plus any
  `w:lvlOverride/w:startOverride`.
- Walk the document **in document order** — the counters are accumulated state.
- Apply `startOverride` the first time that `numId` appears.
- `numFmt` ∈ {bullet, none} → no number, **but still reset the deeper levels**
  so the numbers below do not drift.
- Advance the current level's counter and reset every deeper level (except
  levels with `lvlRestart=0`).
- Render `lvlText`: substitute `%1..%9` with the matching level's counter,
  formatted by **that level's** `numFmt` (`decimal`, `decimalZero`→`%02d`,
  `lowerLetter`, `upperLetter`, `lowerRoman`, `upperRoman`). If a parent level
  never ran, use its `start` value (never emit an empty number).

**Hierarchy comes from `numFmt`, not from `ilvl`.** `ilvl` is not trustworthy:
real documents routinely declare `a) b) c)` at the same `ilvl` as `1. 2. 3.`,
and using it flattens the tree — child sections become siblings of their parent.
The formula:

- `roman` in fmt → `(RANK_ROMAN_UPPER if upper else RANK_ROMAN) + (ilvl-1)`
- `letter` in fmt → `(RANK_LETTER_UPPER if upper else RANK_LETTER) + (ilvl-1)`
- otherwise → `RANK_DECIMAL + max(dots in the number, ilvl-1)`

Keep Word's number in its **original form** (`1.`, `a)`, `1.1.`); do not
re-derive it.

Hand-typed headings (PHẦN, CHƯƠNG, PHỤ LỤC, MỤC, ĐIỀU) are **recognised first**,
ahead of Word numbering, even when the paragraph also sits inside a numbered
list.

## 5. Section name normalization

### 5.1 Cut at the colon

Many sections run the content straight into the heading line ("Hợp đồng bảo
hiểm: là tất cả văn bản thể hiện sự thoả thuận giữa…"). **The name is the part
before the colon**; what follows is content and moves down into the body.

This rule runs at **every length**, not only when the heading exceeds the
ceiling: an 80-character sentence is still a sentence, and using it whole as a
name makes the outline read like prose.

If the part before the colon is **longer than the ceiling**, that colon sits
mid-sentence and is not a name boundary → skip it and go to §5.3.

### 5.2 Flattened table rows

A line of the form `STT: 3.1 | Nội dung: … | Cụ thể: …` always opens with the
index column. Cutting at the first colon, as for an ordinary heading, takes the
**column label** as the name — turning the whole tree into a run of identical
"STT" entries.

Rules:

- Split on `\s*\|\s*`; require at least 2 columns and at least one labelled
  column (`label: value`).
- A column that lost its label counts wholly as the value (the flattening step
  sometimes drops labels).
- Discard empty columns and columns holding only an index
  (`^[\d.,/()\-–\s]*$`).
- The name is the first value **short enough** (≤ ceiling); if there is none,
  take the first value. (A long content column is body text, used only as a last
  resort.)
- Every column empty (a continuation row of a cell spanning several rows) →
  **empty name**, so the section shows as its number alone. Never grab a column
  label as a name.

**A continuation row down to one column** (`3.1.9 Quy định: năm/lần ĐVKD thực
hiện…`): collect the set of column labels from *all* flattened table rows in the
document; if the label opening the line is in that set, strip it and take the
remainder as the name when it is ≤60 characters, otherwise leave the name empty.
(Looked at alone, "Quy định" is indistinguishable from a section name; only
comparing against the whole document reveals it as a column label.)

### 5.3 Cutting by length

Length ceilings:

| Constant | Value | Used for |
|---|---|---|
| `MAX_TITLE_IN_PATH` | 90 | the name as it goes into the outline path |
| `MAX_TITLE_IN_HEADING` | 200 | the name as it is **printed** on the heading line |
| `MAX_NAME_IN_HEADING` | 60 | the "name" ceiling when checking a decimal candidate |
| `MAX_PLAIN_HEADING_LEN` | 160 | ceiling for a line with no colon |
| `MAX_HEADING_LEN` | 250 | absolute ceiling for any heading line |
| `MAX_BANNER_LEN` | 120 | ceiling for a banner |

The 90 and 200 ceilings must stay separate: the outline prefix has to yield
token room to the content, so it is cut at 90, but the heading line printed on
the page has no such constraint — cutting it at 90 breaks mid-phrase ("…làm
nguyên" / "liệu sản xuất") and the model reads a section name with words
missing.

The cut algorithm when a name exceeds `limit`:

1. Take the first `limit` characters.
2. Find the last occurrence of `". "`, `", "`, `"; "` — if it is at or past
   `limit//2`, cut there and return (no `…` appended).
3. Otherwise cut at the last space if it is at or past `limit//2`, else cut
   hard, then append `…`.

### 5.4 An empty name is a conclusion, not a gap

`Phụ lục 01` has no name of its own. Filling it in from `block.text` renders the
path as "Phụ lục 01 Phụ lục 01". The final naming rule:

- A name exists (after column-label stripping) → use it.
- No name **and** (there was an original name, or the whole line equals the
  section number) → empty name.
- Otherwise → take `block.text` verbatim.

## 6. Building the outline tree

- **Compress ranks into consecutive levels**: collect the set of ranks that
  *actually occur* in the document, sort ascending, map to `1, 2, 3…`. A
  document that uses no PHẦN/CHƯƠNG must have `1.` at level 1, not level 5.
- **The tree goes at most 3 levels deep.** From level 4 (`1.1.1.1`) down, a
  heading stops being a branch and becomes content of its parent: splitting that
  far leaves each node holding one or two sentences, its vector carries almost
  no information, and the chunk title grows a pointless level.
- **Demoting** a heading past 3 levels: `kind → "para"`, clear
  `number`/`level`/meta, and **splice the number back onto the front of the
  text** if the text does not already start with it (DOCX keeps the number in
  `block.number` rather than in the text — drop it and the rebuilt document
  loses its numbering entirely, leaving readers unable to check it against the
  original).
- **Content belongs to the nearest heading above it**, whatever page that
  heading is on — which is how a section spanning several pages is handled.
  Every open ancestor must extend its `page_end` so the metadata stays
  consistent.
- **The preamble**: content before the first heading (cover, opening remarks) is
  collected into one section named by `PREAMBLE_TITLE`, with an empty `number`.
  It **parents no section** — on the first real heading, clear the stack. It
  must never be drawn as a heading on output (the name is the tool's invention
  and is not in the document).
- **The path** is `path = [each ancestor's heading_str…] + [f"{number} {title}"]`,
  joined with `" > "`. The displayed `level` is the true depth in the tree
  (`len(stack)+1`), so no level is skipped.

## 7. Merging short sections

A glossary running `1.1 … 1.60`, one or two lines per entry, yields dozens of
chunks of a few dozen tokens — vectors carrying almost no information. Merging
loses that node from the tree, **but loses no words**: the heading line moves
down to open the body.

The algorithm:

- Loop until no mergeable pair is left; **each round merges exactly one pair**:
  take the shortest remaining section and join it to its **smaller** neighbour.
- Consider **both the section above and the one below**. Looking only forwards
  leaves a short section stranded forever behind a huge one.
- The loop lets a parent that has just absorbed all its children be reconsidered
  (a single-pass merge misses that case entirely).

Merge conditions:

- The absorbed section (the **later** one) must be a **leaf** — merging one with
  children would delete a branch.
- The two must share a branch: the same parent, or a parent-child relationship.
  Merging across branches mixes two topics into one vector.
- `is_preamble` and `is_banner` **never** take part in a merge. A banner is only
  a divider, not a topic; filing numbered content under a node that carries no
  number to look it up by is wrong.
- Total tokens after merging ≤ `max_tokens − tokens of the outline prefix`.
  Forget the prefix and the merged section is split in two by the chunker
  anyway — the merge achieves nothing and produces two chunks with one name.

Number normalization after merging (**only when merging two siblings**; when a
child merges up into its parent, the parent's number already covers the child):

- `number` = the numbers joined with `" + "`, **kept in full** — those are what a
  lookup uses. Keeping the old number alone makes the tree lie: the chunk is
  titled `1.1 Mục đích` while holding all of `1.2` as well.
- `title` = the names joined with `" + "`, deduplicated, **trimmed past the
  ceiling** (90 for the path, 200 for the printed line), with the trimmed part
  replaced by `…`.
- Update `path[-1]` to the new `heading_str`.

When moving content across: if the absorbed section's heading line is the first
half of a sentence (by the rule in §2.1), **join it** to the first block rather
than leaving it broken in two; otherwise insert it as its own block
(`bold=True`) at the front.

## 8. Self-check checklist

Once implemented, the output document must pass all of these:

1. No character in U+E000–U+F8FF; no U+200B/FEFF/00AD.
2. No `$`…`$` sequences and no replacement character `�` in the text.
3. Every `section.level ≤ 3`; no skipped levels (level never increases by more
   than 1).
4. Numbers of sections sharing a parent increase monotonically; no section
   carries a zero-padded number.
5. No section has a `title` longer than its corresponding ceiling.
6. No section has a `title` equal to a table column label (`STT`, `Nội dung`,
   `Quy định`…) repeated many times over.
7. Total characters of the output text ≈ total characters extracted (differing
   only by whitespace) — proof that no text was lost.
8. For a DOCX with `numbering.xml`: every paragraph in a numbered list has a
   non-empty `number`.
9. Cross-reference sentences ("theo Điều 5…", "quy định tại Phần 1 này") never
   appear as a section.
